# urlshortener MVP v1 — Go + Gin, VSA + DDD + Hexagonal

URL shortener learning project (first rung of the learning ladder). Single monolith: one Go binary + PostgreSQL. Architecture: vertical slices, tactical DDD, hexagonal ports & adapters with an absolute dependency contract (see S5).

## Specs

- **S1**: Stack: Go + **Gin** + PostgreSQL. User: "me gusta mas Gin" (chi rejected).
- **S2**: Scope v1 ("MVP mínimo"): "Acortar, redirigir, validación de URLs, tests. Sin caché ni analytics."
  - `POST /shorten` with JSON `{"url": "..."}` → `201` with `{"code": "...", "short_url": "..."}`
  - `GET /:code` → `301` redirect to target (`Location` header); unknown code → `404`
  - Invalid URL (not absolute http/https, unparseable) → `422` with error message; rejected input must not persist anything
- **S3**: Identity: Base62 code generated from the sequence; collision with the unique index on `code` retries generation.
- **S4**: Monolith first: one Go binary, one process, one Postgres. User confirmed: "primero un monolito?" → "si".
- **S5**: Architecture contract (user: "una implementa que cumpla sus principios mas importantes y que permitan al software siempre escalar sin complicaciones o modificarse sin tanta complejidad"):
  1. Dependency rule absolute: business core imports nothing external (no Gin, no pgx, no SQL, no system clock).
  2. Every external interaction crosses a core-owned port (repository, code generation, time).
  3. Adapters are dumb translators; all business decisions live in domain or use cases.
  4. Boundaries by business capability (slices): new feature = new slice, existing slices untouched.
  5. Testability proves the design: core tests run without Docker/network/framework; sociable tests vs real Postgres (testcontainers) verify adapters only.
- **S6**: Data model: table `urls(id bigserial PK, code text UNIQUE NOT NULL, long_url text NOT NULL, created_at timestamptz NOT NULL default now())`.
- **S7**: Rich domain (rule #8): `ShortURL` entity with behavior (constructor applies validation + code assignment); no anemic structs, no business logic in handlers or repositories.
- **S8**: Errors: API problems as JSON (RFC 9457 problem details shape), no panics reaching users; unknown routes → 404 JSON.
- **S9** (L8): HTTP responses standardized: one shared problem-details implementation (RFC 9457 complete: `Content-Type: application/problem+json`, meaningful `type` URIs, title/status/detail) used by ALL handlers and the NoRoute fallback; a single domain-error → HTTP-status mapping owned in one place; no hand-copied JSON shapes across slices.
- **S10** (L8): Database migrations use the Go ecosystem standard tool (goose, embedded `embed.FS` SQL files with Up/Down), replacing the hand-rolled migration runner. Ordering, tracking and concurrent-start safety come from the tool, not custom code.
- **S11** (L8, refined L9): Persistence does not leak into the use case: the redirect read port returns the `ShortURL` entity (not raw primitives); the domain provides an explicit rehydration constructor for stored entities (trusted — no revalidation); the adapter maps row → entity. Row structure stays inside the adapter. NO new layer is added: the port + adapter already IS the translation boundary for our own database (user-confirmed principle: a separate ACL layer is only for external models we do not control); T9 completes the adapter's existing translation, it does not stack an ACL on top of it.
- **S12** (L10): Testing pillars, codified: tests must run AS FAST AS POSSIBLE (user principle); assertions are behavior-only — no interaction counting where the count is not the observable contract (fakes model their limits through inputs, e.g. a sequence source that errors after N values, instead of spies); test convention recorded in ADR-002: slice tests enter only via handler (HTTP) or use case (public entry points); doubles exist ONLY as implementations of core-owned ports (hand-written fakes, no mock frameworks); mocking own collaborators is forbidden; each container-based package shares ONE Postgres container across its tests (isolated per-test data), targeting minimal wall-clock feedback.
- **S13** (L12): Centralized error handling and observability: an HTTP middleware is the SINGLE place that renders error responses and logs them. Handlers attach errors to the request (Gin `c.Error()`) and return — no per-handler rendering/logging. Error taxonomy: client errors (4xx) render a well-mapped, user-safe problem message; infrastructure errors (5xx) render a generic problem while the full error chain + request context (method, path, status) is logged via `log/slog` (structured). The user never sees internals; the team debugs from logs.
- **S14** (L14): Application structure standards: `main` is MINIMAL (entry point only: run the app, exit on error) — all bootstrap/wiring lives in an application package (e.g. `internal/app`); ALL environment configuration is read in exactly one place (the platform config package, one `Config` struct — no `os.Getenv`/`envOr` outside it); tests are by layers through public behavior, never coupled to internal structure.
- **S15** (L15, refined L18): Use cases return the DOMAIN CONCEPT closest to what they produced — an entity when they produced one entity (the normal case: `Shorten` returns `(shorturl.ShortURL, error)`; the `Result` struct is deleted; the handler, the presentation adapter, composes the response JSON and the public `short_url` from BaseURL) — or a composed DTO ONLY when they genuinely aggregate several sources into a view (e.g. a future read model). The transport-agnostic test governs both: a use case is written as if it could serve a CLI or a gRPC service, not just the web handler — anything that exists only to shape one transport's response (rendering, formatting, URL composition) belongs to the adapter, never the use case. Mirrors S11's entity-returning read port.
- **S16** (L15): The base62 alphabet is domain knowledge: the domain exports a code-shape predicate (`IsPossibleCode`); the redirect use case consumes it; the duplicated alphabet constant in the redirect slice and its anti-drift cross-check are removed (domain is the shared kernel — consuming domain knowledge from two slices is not slice coupling).
- **S17** (L15): Slice error→problem mapping lives in a dedicated `problems.go` per slice (handlers only attach via `c.Error()`); `httpx` owns the canonical generic-internal problem; the generic 500 problem shape exists exactly once in the codebase.
- **S18** (L15): Middleware is named for what it does: `ErrorHandler` becomes `ProblemRenderer`. It logs ALL attached errors of a request (not only the last), and its cause-chain printer traverses `errors.Join` trees (`Unwrap() []error`), not only single-unwrap chains.
- **S19** (L15): `app.Run` is a thin orchestrator over specific bootstrap functions (logger, database, server lifecycle); each function has one responsibility; `Run` only sequences them.
- **S20** (L15): `platform/postgres` owns ALL Postgres infrastructure: pool connect (`Connect`, pool configured with statement/query timeouts), migration run (its OWN deadline, separate from the connect budget — a slow connect must not starve migrations), and the port adapter. The composition root only orchestrates. `NextSequence` runs on a cancellable context (never `context.Background()`); infrastructure error wrapping uses `%w` (never string concatenation).
- **S21** (L15, from the RFC 9457 reference the user provided): Problem documents are RFC 9457-complete: `instance` member (per-request correlation: request path + generated short id) and extension-member support; titles use the RFC 9457 registered recommendations ("Unprocessable Content" for 422).
- **S22** (L15): ALL tests are behavior-only (S12/ADR-002 applied without residue): the domain package's `gen.calls` interaction counting is replaced by behavior assertions (e.g. an err-on-first-call sequence fake); shorten use-case tests stop pinning the failed collided attempt's internals.
- **S23** (L15): Config behavior is pinned by tests: missing `DATABASE_URL` errors; `PORT` is validated (must be numeric in range) so garbage fails at config time, not at Listen.
- **S24** (L15): Container test scaffolding (TestMain/startE2EPostgres/TRUNCATE isolation) lives in ONE test-only package (`internal/testsupport`); the three container packages consume it; production code never imports it.
- **S25** (L15): Problem details must not echo raw user input: the invalid-URL problem detail is a fixed user-safe message (the offending input reaches only the logs via the cause chain).
- **S26** (L20): The redirect read path is cache-first: the use case orchestrates Get → on miss, Finder → Put. A new core-owned `redirect.Cache` port (`Get`/`Put`, same ownership rule as Finder, S5.2); the core knows THAT a fast source exists, never HOW it caches (S15: transport- and storage-agnostic use case).
- **S27** (L20): Cache resilience rule: a cache failure must NEVER fail the redirect — a Get error is treated as a miss (fall back to the Finder) and a Put error is ignored. A degraded cache degrades performance, never availability; the source of truth remains the database.
- **S28** (L20): it.3 ships the in-memory adapter (Redis is a later iteration implementing the SAME port): a TTL-bounded map with a max-entries cap. Because codes are immutable in v1 (S2), the TTL bounds MEMORY, not consistency — no invalidation exists or is needed. The TTL and cap come from config (single env reader, S14).
